## 板块四 访问控制大全（原第2章 1、15、17、20、26、29、30 条 + 真题二·1·14·18 + 真题三·1 + 真题四·8·9·10）

### 第一道防线 🆕③⭐

- 计算机系统和资源被**未授权访问**时，采取的**第一道防线是访问控制**。

### 四大访问控制模型 ⭐

| 模型 | 核心机制 | 一词记忆 |
| --- | --- | --- |
| **BLP** | 基于**强制访问控制**系统，以**敏感度**划分资源安全级别（保密性） | 敏感 |
| **Biba** | 对数据提供**分级别**的**完整性**保证 | 完整 |
| **Chinese Wall** | 安全策略基础：客户访问的信息**不与目前可支配的信息产生冲突** | 防冲突 |
| **RBAC** | **许可权与角色**联系，用户充当合适角色成员获得该角色许可权 | 角色 |

📌 **BLP敏感 · Biba完整 · CW防冲突 · RBAC角色**

### 全称与缩写（英文对应必背）⭐

| 缩写 | 中文 | 英文全称 |
| --- | --- | --- |
| **DAC** | 自主访问控制 | Discretionary Access Control |
| **MAC** | 强制访问控制 | Mandatory Access Control |
| **RBAC** | 基于角色的访问控制 | Role-based Access Control |
| **SSO** | 单点登录 | Single Sign-On |

### DAC 访问控制矩阵：能力表 vs ACL 🆕②⭐（高频新增）

- DAC 的**理论模型是一个二维矩阵**：**行＝主体，列＝客体**；自主访问控制模型的**实现机制就是通过访问控制矩阵实施**。
- **按行拆 → 访问能力表（Capability）**：站在**主体**视角——该主体能访问哪些客体
- **按列拆 → 访问控制表（ACL）**：站在**客体**视角——哪些主体能访问该客体

📌 **行主能力、列客 ACL**（横着看"我能干啥"＝能力；竖着看"谁能动我"＝名单）

### 访问控制的三种"分类" ⚠️

| 分类视角 | 类别 |
| --- | --- |
| 按实现方式分 🔖🆕②🆕④ | **行政性 · 逻辑/技术性 · 物理性**访问控制 |
| 按模型分 | DAC（自主）· MAC（强制）· RBAC（角色） |
| 按作用/目的分 🆕④ | **预防性 · 纠正性 · 探查性**访问控制 |

📌 **实现＝行技物；目的＝预（预防）·纠（纠正）·查（探查）**

### 访问控制管理三依赖 🆕④⭐

访问控制管理主要依赖：**用户账户管理 · 操作跟踪 · 访问权利和许可权的管理**

📌 **管账户、跟操作、管权限**

### 自主访问控制 DAC 的定义

由**客体属主自主管理**：由宿主自己决定是否将自己的客体访问权（或部分访问权）**授予其他主体**，这种控制是"自主的"。

### 分布式访问控制（三种方法）⭐

`单点登录 SSO · Kerberos 协议 · SESAME`

**Kerberos 协议要点** ⭐：

- 支持**双向**身份验证
- 通过**交换跨域密钥**实现**分布式网络环境**下的认证
- **AS 和 TGS 是集中式管理**，容易形成**瓶颈** ⚠️
- 身份认证采用**对称加密**机制

## 板块五 密码学核心（原第2章 4、5、7、8、10、12、13、18、19、22、23、24、27 条 + 真题二·2·17）

### 学科与设计思想

- 密码学 = 密码**编码**学 + 密码**分析**学
- 对称密码用**乘积迭代**达到**扩散与混淆**
- 传统对称密码加密使用的两个技巧：**代换 和 置换** 🆕②

### 对称 vs 非对称 ⭐

|  | 对称密钥 | 非对称密钥 |
| --- | --- | --- |
| 优点 | 加解密速度快、资源消耗低、实现简单 | 密钥分发简单、管理方便、支持数字签名、安全性高 |
| 缺点 | 密钥分发难、管理复杂、**缺乏不可否认性** | 加密慢、资源消耗大、密钥长 |

### 算法归类 ⭐

| 类型 | 算法 |
| --- | --- |
| 序列密码（每一次加密一位/一个字符） | RC4、SEAL |
| 分组密码（每一次加密一个明文分组） | DES、IDEA、AES |
| 消息摘要 | MD5、SHA 系列、RIPEMD |

📌 **序列=RC4/SEAL；分组=DES/IDEA/AES；摘要=MD5/SHA/RIPEMD**

### 分组密码工作模式 ⭐🔖🆕②

> 工作模式 = 刻画如何利用分组密码提供信息安全服务

`ECB（电码本）· CBC · CFB（密文反馈）· OFB（输出反馈）· CTR` 📌 **五模式：ECB/CBC/CFB/OFB/CTR**（电码本、密文反馈、输出反馈名字必背）

**各模式特点（真题第二批）** ⚠️：

- **ECB**：分组密码的**基本**工作模式
- **CBC**：每一分组的加密都依赖于**所有前面的分组**；与 ECB 一样要求数据长度是密码分组长度的**整数倍**
- **OFB**：将一个分组密码**转换为一个序列密码**，具有普通序列密码的优缺点

📌 **ECB 是基本、CBC 串前面、OFB 变序列**

### 哈希 / 摘要长度速记 ⭐🔖

| 算法 | 长度 |
| --- | --- |
| **MD5** | **128 位** |
| **SHA**（SHA-1） | **160 位** |
| **SHA-2** | **224 / 256 / 384 / 512** 比特 |
| **SHA-3** | **224 / 256 / 384 / 512** 比特 |
| **AES 分组长度** | **128 比特** ⚠️（是"分组长度"不是摘要） |

📌 **MD5 128、SHA 160；SHA-2/3 四兄弟 224/256/384/512；AES 分组 128**

### 密钥四分类（按用途）⭐

| 密钥 | 用途 |
| --- | --- |
| **初始密钥** | 设备初始化和安全连接建立 |
| **基本密钥** | 设备长期存储和本地数据保护 |
| **会话密钥** | 实时通信和数据传输 |
| **密钥加密密钥** | 密钥分发和权限控制 |

📌 **初始建、基本存、会话传、加密管**

### 三大"数学难题"算法与 RSA 推导 ⭐

| 算法 | 依赖难题 | 要点 |
| --- | --- | --- |
| **RSA** | 大整数因式分解 | 加密公式`c = m^e mod n` |
| **ElGamal** | 离散对数 | — |
| **Diffie-Hellman** | 密钥交换协议：第一个在非保护信道中创建共享密钥的方法 | 匿名（无认证）→ 存在**中间人攻击**风险 |

**RSA 密钥推导链**：知 n → 分解出 p、q → 算 **φ(n)** → **e×d ≡ 1 (mod φ(n))**，即 **e·d = nk + 1**

### 签名 vs 加密（谁用谁的密钥）⚠️⭐

| 操作 | 用谁的密钥 |
| --- | --- |
| **签名** | **A 的私钥签名，A 的公钥验签**（与 B 没关系） |
| **加密** | **A 用 B 的公钥加密，B 用 B 的私钥解密**（与 A 的公私钥没关系） |

📌 **签名用自己（私签公验），加密用对方（他加他解）**

| **数字签名** | 发送方否认 · 接收方否认 |

## 板块六 身份认证与 PKI · AAA（原第2章 2、3、14、21、25 条 + 真题一·2 + 真题二·7 + 真题三·19）

### 身份验证方式（3 种）⭐

`静态密码 · 动态口令 · USB Key 认证`

### USB Key 认证（细节必背）⭐

- 采用**软硬件相结合、一次一密**的**强双因子**认证模式
- 是一种 **USB 接口的硬件设备**，内置**单片机或智能卡芯片**
- 可存储用户的**密钥或数字证书**，利用内置**密码学算法**实现身份认证
- **两种应答模式** ⭐：① 基于**挑战/应答**的认证模式；② 基于 **PKI 体系**的认证模式
- PKI 体系的认证模式采用的身份认证手段 = **USB Key 认证** 🔖

### 数字证书与数字签名 ⚠️

- **数字证书内容 6 项**：`证书序列号 · 证书持有者名称 · 证书颁发者名称 · 证书有效期 · 公钥 · 证书颁发者`
- **数字签名安全服务 3 项**：`鉴别（认证）· 完整性 · 不可否认性` ⚠️（原笔记"不可依赖"应为"不可否认"）
- **CA 通过发布证书黑名单（CRL），公开发布已经废除的证书** 🆕③
- 1994 年 **DDS** 数字签名标准 🔗板块二

### PKI 体系 ⭐🔖

- 核心 = **CA 认证中心**（颁发、管理数字证书）
- **一个典型的 PKI 系统包括（5 部分）**🔖：`CA（证书颁发机构）· 安全策略 · RA（证书注册机构）· CDS（证书发布系统）· PKI 应用接口` 📌 **CA 发证、RA 注册、CDS 发布，外加策略和接口**

### PKI 六种信任模型 🆕②⭐

`单级 CA 信任模型 · 严格层次结构模型 · 分布式（网状）信任模型 · Web 信任模型 · 桥 CA 信任模型 · 用户为中心的信任模型`

📌 **单级、层次、网状、Web、桥 CA、用户中心**

### AAA 协议：RADIUS vs Diameter（⭐ 必背对比表）

**AAA = 认证（Authentication）、授权（Authorization）、计费（审计）（Accounting/Audit）**；Diameter 和 RADIUS 是两种核心 AAA 协议。

| 对比维度 | RADIUS | Diameter |
| --- | --- | --- |
| 传输层协议 | **UDP**（无连接，尽力而为） | **TCP 或 SCTP**（面向连接，可靠传输） |
| 通信模式 | 仅支持**客户端发起**请求 | 支持**客户端和服务器双向**发起请求 |
| 安全性 | 仅**逐跳加密**（如 IPsec） | 支持**端到端加密**（TLS/DTLS） |
| 扩展性 | AVP 空间有限（**8-bit**），扩展性差 | AVP 空间巨大（**32-bit**），支持**能力协商**，扩展性极强 |
| 可靠性 | 无强制故障切换和心跳机制 | 定义**故障切换（failover）**和**看门狗（watchdog）**机制，确保高可用 |
| 代理支持 | 无内置代理概念，假设直连 | 内置**中继（Relay）、代理（Proxy）、重定向（Redirect）**等节点角色 |
| 应用标识 | 无应用 ID 概念 | 通过**应用 ID（Application ID）**区分不同服务 |
| 标准文档 | **RFC 2865** | **RFC 6733** |

**补充要点** ⭐：

- **Diameter** 支持移动 IP、**NAS 请求**和移动代理的**认证、授权和审计**；实现和 RADIUS 类似，但采用 **TCP** 协议，支持**分布式审计**；**克服了 RADIUS 的许多缺点，是最适合未来移动通信系统的 AAA 协议** ⚠️（原笔记此句误粘在 DAC 条目下，实为 Diameter 特点）
- **RADIUS** 全称 = **远程认证拨号用户服务**（拨号用户远程认证服务），侧重于**网络接入**
- **TACACS** 全称 = **终端访问控制器访问控制系统**；原始 TACACS 侧重于**终端设备管理**

📌 **RADIUS 拨号接入走 UDP；Diameter 移动通信走 TCP/SCTP 更可靠**

**IPSec 协议族三件套** ⭐🔖：

| 协议 | 要点 |
| --- | --- |
| **IKE** | **混合型协议**，由 **ISAKMP + Oakley + SKEME** 组成 |

**TCP 三次握手** 🆕③⭐（新增必考）：

- **信任根 和 信任链**是可信计算平台最主要的关键技术之一。

### 信息安全管理 🆕②

- 信息安全管理主要内容（3 部分）：**管理体系 · 风险评估 · 管理措施**
- **ISMS**（ISO/IEC 27001）按 **PDCA**（策划-实施-检查-处置）建设运行 ⭐；管理与技术并重

### 风险评估 🆕③

- 风险评估分为：**自评估 · 检查评估**
- 风险四要素：`资产 · 威胁 · 脆弱性 · 风险`；**风险 ≈ 资产 × 威胁 × 脆弱性**

### 应急与连续性 🔖⭐

- **应急计划三要素**：`事件响应 · 灾难恢复 · 业务持续性计划` 📌 **应、灾、业**
- **BCP** 业务持续性计划 / **DRP** 灾难恢复计划；两大指标 ⭐：**RTO** 恢复时间目标 / **RPO** 恢复点目标

📌 **RTO=多久能恢复；RPO=能丢多少数据**

### 数据与系统 🆕②

- 分类数据管理包括这些数据的**存储、分布、移植和销毁**
- 标准信息系统组成部分：**服务器、网络设备和保护设备**；也就是说包括**硬件、软件、数据和信息**
- 制度：人员（权限、离岗）· 机房 · 密钥 · 日志审计

## 板块九 标准与法规（原第7章 + 真题一·16 + 真题三·14·23 + 真题四·6·11·20，TCSEC 从第1章并入）

### 标准组织

- 国际：**ISO · IETF · ITU-T**；我国：全国信息安全标准化技术委员会 **TC260** → 发布 **GB/T** 系列

### 评估 / 分级标准 ⚠️别混

| 标准 | 要点 |
| --- | --- |
| **TCSEC**（美国彩虹系列） | 可信计算机系统评估准则：**4 级 7 层 D, C1, C2, B1, B2, B3, A1** ⭐（原第1章考点并入） |
| **CC 通用准则**（ISO 15408 / GB/T 18336） | 国际公认信息技术安全评估准则 |

📌 **4 级 7 层：D、C1C2、B1B2B3、A1**（D 最低，A1 最高）

### 等级保护 ⭐

- 流程：`定级 → 备案 → 建设整改 → 等级测评 → 监督检查` 📌 **定备改测监**
- **基本安全要求中，基本技术要求从 5 个方面提出** 🔖🆕④：`物理安全 · 网络安全 · 主机安全 · 应用安全 · 数据安全及备份恢复`（真题四表述为"物理、网络、主机、应用、数据安全"）📌 **物网主应数**
- **安全保护等级由两个因素决定** 🆕④⭐：① 等级保护对象受到破坏时**所侵害的客体**；② **对客体造成侵害的程度** 📌 **侵谁（客体）＋侵多深（程度）**
- **《信息系统安全保护等级划分准则》定级 4 要素** 🆕④⭐：`信息系统所属类型 · 业务数据类型 · 信息系统服务范围 · 业务自动化处理程度` 📌 **系统类型 · 数据类型 · 服务范围 · 自动化程度**

### 管理标准 ⚠️

ISO/IEC **27001** = 管理体系"要求"（可认证） vs **27002** = "实践指南" 🔗板块八 ISMS
