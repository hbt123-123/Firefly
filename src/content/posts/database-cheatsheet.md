## 板块一 基础概念（原第1、3、4章）

### 三级模式 + 两级映像 ⭐ 必背

| 三级模式 | 含义 |
| --- | --- |
| **外模式** | 用户/应用程序看到的**局部**数据逻辑结构 |
| **模式** | 数据库**全体**数据的逻辑结构 |
| **内模式** | 数据在存储介质上的**物理**结构 |

| 两级映像 | 提供的独立性 |
| --- | --- |
| 外模式/模式映像 | **逻辑独立性** |
| 模式/内模式映像 | **物理独立性** |

📌 **"外模内"三级；外/模→逻辑独立，模/内→物理独立**

### 其他基础散点（集中背）

- **数据模型三要素** ⭐：`数据结构 · 数据操作 · 完整性约束`
- 关系是**动态**的，关系模式是**静态**的 ⚠️
- 概念模型：对**实体集**命名，对**实体不**命名
- 每 TPS 代价：只用于衡量系统**性价比**的指标
- **粒度** ⭐：粒度越小 → 细节程度越高 → 能回答的查询越多

## 板块二 开发流程一条线（原第1、4章合并）⭐

主背这条链（五字诀：**规·需·设·实·维**）：

`项目规划 → 需求分析 → 系统设计 → 实现与部署 → 运行与维护`

### ① 项目规划（5 项）

`确定目标与范围 · 规划与分析（系统规划与定义、项目规划、可行性分析）· 分解定义工作活动与任务 · 估算项目规模与资源 · 制定项目计划`

- **系统规划与定义 5 要素**：`陈述 · 目标 · 范围 · 边界 · 视图`

### ② 系统设计：概念 → 逻辑 → 物理 ⭐

| 设计阶段 | 产出 | 口诀 |
| --- | --- | --- |
| 概念设计 | ER 图 + 系统总体框架 | 概念=ER图 |
| 逻辑设计 | 一结构(逻辑结构) + 两概要(应用程序概要、事务概要) | **一结构两概要** |
| 物理设计 | 一结构(物理结构) + 两详细(应用程序详细、事务详细) | **一结构两详细** |

- **规范化** → 逻辑设计；**去规范化** → 物理设计 ⚠️
- **完整性约束** → 逻辑模型

各模型包含内容（与上面互相印证）：

| 模型 | 包含内容 |
| --- | --- |
| 概念模型 | ER 图 · 数据字典 · 数据流图 |
| 逻辑模型 | 规范化 · 分解 |
| 物理模型 | 存储结构 · 去规范化 · 索引 · 编写建表语句 |

### ③ 实现与部署（5 项）↔ 实施工作（4 项）⚠️ 两表对照着背

| 实现与部署（原第1章，5 项） | 实施工作（原第4章，4 项） |
| --- | --- |
| 建立数据库结构 | 建立数据库 |
| 数据加载 | 装载数据 |
| 事务和应用程序编码及测试 | 编写与调试应用程序 |
| 系统集成测试与试运行 | 数据库试运行 |
| 系统部署 | — |

📌 内容几乎重叠：考"**实施工作**"答 **4 项**，考"**实现与部署**"答 **5 项**

### ④ 事务概要设计（4 项）

`名称 · 关系 · 逻辑 · 用户` 🔗 它就是逻辑设计"**两概要**"之一（应用程序概要、事务概要）

### 软件开发模型（特征选择题）⭐

| 模型 | 特点 | 关键词 |
| --- | --- | --- |
| **瀑布模型** | 最严格：线性、阶段不可回退 | 严格 + 明确 |
| **快速原型模型** | 快速构建原型验证需求 | 快 |
| **螺旋模型** | 灵活性最高（迭代+风险分析）、**可恢复**、最不严格 | 严格 + 快 |

**螺旋模型四阶段**：`项目规划 → 风险评估 → 工程实现 → 用户评估`

## 板块三 需求分析与建模工具（原第2章 + 真题 1）

### 建模方法 ⚠️ 编号别混

| 方法 | 用途 |
| --- | --- |
| **DFD · IDEF0 · UML** | 需求建模（三大） |
| **IDEF1X** | **数据**建模 ⭐ |
| **IDEF2** | **动态**建模 ⭐ |

### UML 四层概念架构 🔖 ⭐

`元元模型 > 元模型 > 模型层 > 用户模型`（由抽象到具体） 📌 **元元 → 元 → 模型 → 用户**，四层从抽象到具体

### DFD 四元素与符号 ⭐ 必背

| 元素 | 符号 | 作用 |
| --- | --- | --- |
| 数据流 | **箭头** | 处理功能的输入/输出 |
| 处理 | **矩形框** | 对数据逻辑处理、改变数据值 |
| 数据存储 | **圆角矩形** | 数据保存的地方 |
| 外部项 | **斜四方形** | 系统之外与系统有联系的人/事物，说明数据来源与去处 |

📌 **流箭头、处理矩、存储圆矩、外项斜四**

- 分析方法：**自顶向下、逐步细化**的结构化分析方法

### DFD 两条规则 ⭐

1. 任何一个处理：至少有一个**输入流** + 一个**输出流**
2. 一个存储：必须有**流入**的数据流 + **流出**的数据流

## 板块四 ER 与 IDEF1X：图 → 关系模式（原第3章）

### 图形符号

- **ER 图** ⭐：矩形=实体 · 椭圆=属性 · 菱形=联系
- **IDEF1X** ⚠️：独立实体集=**矩形框** · 从属实体集=**圆角矩形框**

### IDEF1X 联系（按原笔记表述，⚠️ 建议与教材核对）

- 1 对 1 → **标定联系**；1 对多 → **非标定联系**；多对多 → **非确定联系**
- **非标定联系不会产生从属实体集**

### ER 图 → 关系模式转换公式 ⭐ 必背

> **关系模式个数 = 实体个数 + 多对多联系个数**

## 板块五 码与数据依赖（原第3章）

| 概念 | 一句话 |
| --- | --- |
| **候选码** | 能唯一标识记录的**最小**字段组合 |
| **主码** | 从所有候选码中**选一个**作表的唯一标识符 |
| **超码** | 能唯一标识记录、**可含冗余字段** |

📌 **候选最小、主码选一、超码可冗余**

- **函数依赖 = 属性依赖**
- 元组的每个属性对应一个**域**（域 = 属性取值范围）

## 板块六 完整性约束（原第3、4章全部合并）⭐

### 三大完整性（按"保护什么"分）

| 完整性类型 | 关键字 |
| --- | --- |
| **实体完整性** | `PRIMARY KEY` |
| **参照完整性** | `FOREIGN KEY` |
| **用户定义完整性** | `CHECK · NOT NULL · UNIQUE` |

📌 **实体=PK、参照=FK、用户定义=CHECK/NOT NULL/UNIQUE**

### 按"作用范围"分（4 级）

| 级别 | 作用范围 | 例子 |
| --- | --- | --- |
| **关系（表级）约束** | 同表**跨行** | UNIQUE |
| **数据库级约束** | **跨表格** | FOREIGN KEY |
| **元组约束** | 同行**不同列** | CHECK |
| **列级约束** | **列内**条件筛选 | NOT NULL |

快速映射 ⭐：`CHECK → 元组；UNIQUE → 关系`

### ⚠️ 三个分类维度对照（原笔记出现过的所有说法，一表理清）

| 视角 | 分类结果 |
| --- | --- |
| 按**完整性类型** | 实体=PK；参照=FK；用户定义=CHECK/NOT NULL/UNIQUE（原第4章） |
| 按**作用范围** | 关系(跨行)/数据库(跨表)/元组(同行不同列)/列级(列内)（原第4章） |
| 按**关键字简记** | UNIQUE·FK·PK→关系约束；NOT NULL→列约束；CHECK→元组约束（原第3章） |

📌 只需记两条主线：**完整性类型** + **作用范围**，关键字映射可推导。

🔗 GRANT、DDL 等 SQL 关键词语句 → 见**板块十**

## 板块七 索引与文件组织（原第3章 + 真题 12）

### 索引规则大全 ⭐

| 规则 | 内容 |
| --- | --- |
| **聚集索引** | 一个表**只能有一个**；键值**可以重复**；支持单列 + 复合索引 |
| **非聚集索引** | 一个表可以**多个** |
| **唯一索引** | 可有多个；作用=保证索引键**不重复**；**不一定是聚集索引** ⚠️ |
| **主索引** | 聚集索引（可主可辅） |
| **有序索引** | 查**范围** + 点查询；**稀疏索引**属于有序索引 |
| **散列索引** | **点**查询，需**精准查询** |

📌 **聚集唯一一、非聚集多；有序查范围、散列查点**

### 索引关键字对应 🔖 ⭐

`UNIQUE` = 唯一索引 · `NONCLUSTERED` = 非聚集索引 · `CLUSTERED` = 聚集索引

### 索引适用 / 不适用场景 ⭐

| 适合建立索引 | 不适合建立索引 |
| --- | --- |
| 频繁查询的列 | 经常更新的列 |
| 经常用于连接的列 | 查询中很少使用的列 |
| 经常用于 WHERE 子句的列 | 数据量小的表 |

### 文件组织 ⚠️ 对应用途

| 文件组织 | 适用场景 |
| --- | --- |
| 聚集文件 | **多表连接** |
| 顺序文件 | 顺序存储、插入删除 |
| 散列文件 | 直接存取、**精准查询** |
| 堆文件 | 更新频繁、文件少 |

- 事务基本表交叉 → 适合**建立合适的索引** + 设计**更有效的文件组织方式**

## 板块八 事务与并发控制（原第4章 + 第3章吞吐量 + 真题 14）

### ACID 四特性 ⭐ 必背

| 特性 | 含义 |
| --- | --- |
| **原子性** | 所有操作**要么全做(do)、要么全撤销(undo)**，可回滚 |
| **一致性** | 事务开始前与结束后，数据库完整性**不被破坏** |
| **隔离性** | 并发读写交叉执行时，**降低数据不一致**的可能性 |
| **持久性** | 事务处理后，数据是**永久**的 |

### 锁 ⚠️

| 锁 | 权限 |
| --- | --- |
| **排他锁（X 锁）** | 既可**读**又可**写**（事务 Ti 获得数据项 Q 上的 X 锁） |
| **共享锁（S 锁）** | 只能**读**，不能写 |

📌 **X=读写；S=只读**

### 两段锁协议（2PL）⭐

1. 所有事务必须分为**加锁**、**解锁**两个阶段
2. 读取数据前，须**申取（申请获得）**对该数据的封锁
3. **释放一个封锁之前，不能申请任何其他封锁**

### 检查点技术 🔖 ⭐

**检查点技术可减少日志恢复技术的操作**（恢复时不必扫描全部日志）

### 避免死锁 5 法 ⭐

`使用绑定连接 · 同一资源按顺序访问 · 避免用户交互 · 采用小事务模式 · 多用行锁、少用表锁`

### 提高事务吞吐量 4 法（原第3章）🔗 与锁/隔离级别联动

`事务大化小 · 改单一磁盘 · 降低隔离级别 · 使用行级锁`

📌 两张清单都有"行级锁""小事务"，**放一起记**：死锁5法 vs 吞吐量4法

## 板块九 应用体系结构（原第4章）

### 功能视角四层 ⭐

| 层次 | 职责 |
| --- | --- |
| **表示层** | 用户交互 |
| **业务逻辑层** | 表示层与数据访问层的**桥梁**（设计、构建） |
| **数据访问层** | 数据的保存/读取，访问关系数据库（**DBMS**） |
| **数据持久层** | 数据持久化；物理层与访问层之间；**DBAS + 存储介质** |

📌 **表、逻、访、持**

### C/S vs B/S ⭐⚠️

| 体系 | 业务逻辑在哪 | 事务逻辑在哪 |
| --- | --- | --- |
| **C/S** | 客户端 | 数据服务器 |
| **B/S** | 应用服务器 | 数据服务器 |

- **三层 B/S**：业务规则 → **应用服务器**；事务规则 → **数据库服务器** ⭐

⚠️ **应用服务器只查不存**

📌 **业务逻辑 C 端/B 端分开记；事务逻辑永远在数据服务器**

## 板块十 SQL 语句与编程考点（原第2、3、4章 + 真题 2、3、4、9、10、11、13）

### 数据定义与安全

- **DDL**（数据定义语言）→ 放在**数据字典**中 ⭐
- **GRANT** = 定义数据库**安全**（授权）的语句 ⭐；授权语句格式 🔖： `GRANT <权限> ON <表名> TO <用户名>`
- **DROP vs DELETE** 🔖 ⚠️：**DROP 删除结构**（用户、表、库）；**DELETE 删除数据** 📌 **DROP 拆房子，DELETE 搬家具**

### 查询：分组与排序 🔖 ⭐

- **分组 = GROUP BY**；**排序 = ORDER BY**
- 📌 **分组 group、排序 order**

**ORDER BY 六条** ⭐： ① 按指定列对**结果集排序** ② 默认**升序** ③ 可**多列排序**（此时排列是嵌套的） ④ 只能作为其他子句的**最后一个子句** ⑤ **视图**中可以使用 ⑥ **子查询中不可以使用** ⚠️

### 排名函数四兄弟（SQL Server 2008）🔖 ⭐

| 函数 | 规则 |
| --- | --- |
| **RANK** | 并列后**跳过**，排名**有间断** |
| **DENSE_RANK** | 并列后**不跳过**，排名**连续** |
| **ROW_NUMBER** | 每行**唯一**排名，无并列 |
| **NTILE(n)** | 将数据**均分为 n 组**，返回**组号** |

📌 **有跳 RANK、稠密 DENSE、行号 ROW、分桶 NTILE**

### 存储过程 🔖 ⭐

- 可以接受**多个输入参数和输出参数**
- **输入参数**：不需要注明；**输出参数**：需要注明 **OUT 或 OUTPUT** ⚠️
- **DECLARE 声明不能用 OUTPUT** ⚠️

## 板块十一 分布式与并行数据库（🔖 真题新增）

### 分布式数据库最基本特征（3 个）🔖 ⭐

`本地自治 · 非集中式管理 · 高可用性` 📌 **自治、非集中、高可用**

### 并行结构 🔖 ⚠️

- **共享磁盘**结构：只共享**磁盘**，**不共享内存**

### 数据划分 🔖 ⚠️（别选反）

- **范围划分**：会**降低分布的均匀性**，**降低并行处理能力**

### 快照 🔖

- 快照只适合**数据量较小**的表
